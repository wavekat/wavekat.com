WaveKat · a debugging story

A space broke
our app.

Not a space in the code. A space in our own name.

What it was supposed to do

Click a phone number on a web page — a supplier, a customer, anyone — and our phone app comes up with the number already typed in.

For that, the app asks the operating system a favour: when someone clicks a phone number, send it to me. Same kind of request a browser makes when it wants to be your default browser.

Then two things disagreed

the switch in Settings
“Couldn't set up phone links.”
the actual operating system
Delivering clicked numbers correctly. Since install.

The system was doing the thing. The check that asked “are you doing the thing?” kept answering no.

It takes the first word

To double-check its own work, the system tool reads the line that says where our app lives — then splits it on spaces.

Exec="/opt/WaveKat Voice/@wavekatvoice-desktop" %U
✗The quotes exist precisely so a path can contain a space. It doesn't look at them.
✗So it goes looking for a program called "/opt/WaveKat. There isn't one.
✗Lookup fails → tool errors out → the answer that reaches us: you're not the default.

Nobody chose that folder

✓Naming the product two words is fine.
✓Installing under /opt/<product name> is the convention.
✓Quoting a path that contains a space is exactly right.

Every step correct. Feature dead on an entire operating system.

Why it died completely

We only save the setting if the system confirms the change worked — so the switch can never claim “On” while nothing happens.
The check failed, so the setting never saved.
Setting not saved, so the app treated the feature as off.
Feature off, so every clicked number was quietly dropped — while the OS kept faithfully delivering them.

An honest rule, faithfully passing along a wrong answer.

The fix: ask a different question

Not “did my change work?” — that goes back through the same broken machinery.

But “who is the default for phone links right now?” — which just reports the name on file. It never works backwards from a name to a program, so it never reads that line, so it never trips over the space.

When it says our name back to us, we call it success — whatever the first tool claimed.

What I took from it

When a check disagrees with reality,
suspect the check.

“Did my change succeed?” and “is this true right now?” look like the same question. They aren't. The first one inherits every bug in the machinery that made the change. The second one just looks.

When you can — look.
